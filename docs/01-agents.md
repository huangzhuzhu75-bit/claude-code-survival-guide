# 01｜都是 Opus 5.5，为什么我还是用 Claude Code？

[返回首页](../README.md)

先声明：**我个人用了一个月 Claude Code Pro**，也算 Opus 5.5 的重度用户。说实话，最初就是看上模型性能和 Claude 在前端 UI 上那股独特的审美。

我自己做独立游戏，需要 AI 长时间维护项目，而不是写两段代码就结束。所以我更在乎 Agent 能不能真的把任务做完。

### Claude Code

官方原生适配，Skills、MCP、Hooks、子 Agent 工作流比较完整。复杂项目长期迭代很顺手；缺点是额度、认证、配置和订阅体验有时挺折腾。

### Cursor

IDE 体验舒服，边写边看改动很直观；但重度使用高档模型的成本可能不低。

### OpenCode

开源、多模型、自定义自由度高。要付出配置时间，选用 Opus 之类模型时通常还得考虑独立供应商计费。

### Grok Bot

入门容易，支持多模型路由。我个人不太喜欢路由不可完全控制、额度少、质量可能有波动的体验。具体模型可用性取决于对应平台和套餐，别把路由名称当成每次实际调用的保证。

**我的选择逻辑：模型负责能力上限，Agent 负责把能力落地。** 复杂项目我暂时更偏向 Claude Code，但不觉得每个人都必须和我一样。

后面更重要的不是模型拉踩，而是 [把环境、认证和使用流程弄明白](00-start-here.md)。
